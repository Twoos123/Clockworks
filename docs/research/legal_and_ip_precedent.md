# Legal, Licensing, and Rights-Holder Landscape for a Fan Browser Port of Spiral Knights (as of 2026-10-12)

Scope note: These notes separate (F) established fact with source, (I) reasonable inference, and (Q) open legal question. Nothing here is legal advice. Research was done 2026-10-12 via web search and page fetches; several forum pages and the GitHub DMCA archive were sampled, not exhaustively read.

---

## KQ1. What has happened to comparable fan ports, decompilations, engine reimplementations, and private servers? (Precedents with outcomes)

### Takeaway
The pattern across 2016–2026 is consistent: projects that redistribute the rights holder's compiled code or assets, run a competing service for a *live* game, monetize, or connect modified clients to official servers get taken down (and sometimes sued or arrested); projects that ship only their own code, require users to supply their own legally obtained game files, stay non-commercial, and avoid trademarks have, with few exceptions, been left alone or eventually licensed. Decompilation itself sits in the middle: it has survived when the output is an engine that needs the user's copy (sm64, OoT/Ship of Harkinian, pokeemerald, RSDK) and has been attacked when the output is a redistributable, playable copy (Eaglercraft, the compiled sm64 PC port, PSO Reborn in Sept 2026) or when the rights holder is litigious (Take-Two vs. re3).

### Cited Findings

#### Eaglercraft (Minecraft in the browser via decompilation + TeaVM) — Mojang/Microsoft, 2023
- (F) In Feb 2023 Mojang had GitHub remove 92 Eaglercraft repositories, alleging infringement of copyrights and trademarks; a repository of decompiling tools/instructions initially stayed online — [TorrentFreak, 2023-02-24](https://torrentfreak.com/mojang-targets-repositories-of-browser-based-minecraft-copy-eaglercraft-230224/)
- (F) The 2023-03-13 notice (filed by an enforcement agent for Mojang AB) against github.com/PrecisionClient/eaglercraft claimed: the MINECRAFT trademark (U.S. Reg. 4,252,394); 15 U.S. copyright registrations for artwork/character designs; and a §1201 anti-circumvention theory describing Azure AD sign-in/license checks, compiled code and encrypted sub-components as technological measures. It stated the developer "presumably decompiled and reverse engineered" portions of the code and cited EULA clauses against redistribution/commercial use. GitHub processed it against a fork network of 364 repositories — [github/dmca 2023-03-13-mojang-2.md](https://github.com/github/dmca/blob/master/2023/03/2023-03-13-mojang-2.md)
- (F) GitHub's note on that notice: it "did not find sufficient information to determine a valid anti-circumvention claim" but found other valid copyright claims; it contacted repo owners with counter-notice information before disabling — [github/dmca 2023-03-13-mojang-2.md](https://github.com/github/dmca/blob/master/2023/03/2023-03-13-mojang-2.md)
- (F) A May 2023 Mojang notice argued that exact source code or pixel-perfect images need not be present in a repo for it to infringe (same mechanics/textures/UX theory) — [github/dmca 2023-05-10-minecraft.md](https://github.com/github/dmca/blob/master/2023/05/2023-05-10-minecraft.md); summarized in [TorrentFreak, 2023-04-24](https://torrentfreak.com/mojang-continues-crackdown-on-minecraft-pirates-230224/)
- (F) Mojang escalated beyond GitHub: a GitLab account and a Discord server were shut down; Google delisted eaglercraft.ru from search; a Cloudflare request against eaglercraft.ru had no result. Lead developer lax1dude wrote he was not interested in fighting the DMCA complaints, said the goal was never piracy, voluntarily removed code from his own site, then took the EaglercraftX 1.8 repository (decompile tools/instructions for Minecraft 1.8) offline, and asked Mojang to talk. The separate eaglercraft.ru operator kept the site up, ad-funded at roughly $1,000–2,000/month — [TorrentFreak, 2023-04-24](https://torrentfreak.com/mojang-continues-crackdown-on-minecraft-pirates-230224/)
- (F) One of the 2023 GitHub notices was processed against a network of 284 repositories; GitHub's 2023 transparency data showed Eaglercraft as a major contributor to that year's 20,517 takedowns — [TorrentFreak, 2024-03-08](https://torrentfreak.com/dmca-notices-took-down-20517-github-projects-last-year-240308/)
- (F, weak source) A wiki entry lists an "EaglercraftX u51" stable release dated 2025-05-19 and says DMCA pressure "effectively halted official development"; the project reportedly moved to self-hosted Git — [EverybodyWiki](https://en.everybodywiki.com/Eaglercraft); self-hosting claim from [HandWiki](https://handwiki.org/wiki/Software:Eaglercraft). Neither is primary.
- (F) Sources conflict on which enforcement agent sent the first notice (Tracer AI vs. AppDetex) — [HandWiki](https://handwiki.org/wiki/Software:Eaglercraft) vs. [minecraft-hosting.pro](https://www.minecraft-hosting.pro/article/177-what-is-minecraft-eaglercraft). Unverified.

#### re3 / reVC (GTA III / Vice City reverse-engineered source) — Take-Two, 2021–2023

#### Reverse-engineering case law and the DMCA (context)
- (F) Sega v. Accolade, 977 F.2d 1510 (9th Cir. 1992) and Sony v. Connectix (9th Cir. 2000) held intermediate copying during reverse engineering for interoperability can be fair use where the final product contains none of the plaintiff's code; both are Ninth Circuit decisions; Atari v. Nintendo is distinguished — [Copyright Office summary of Connectix](https://www.copyright.gov/fair-use/summaries/sony-connectix-9thcir2000.pdf); [Wikipedia: Sony v. Connectix](https://en.wikipedia.org/wiki/Sony_Computer_Entertainment,_Inc._v._Connectix_Corp.); [Duke CS fair-use notes](https://courses.cs.duke.edu/cps182s/fall02/cscopyright/Copyrights/Copyright-Fairuse.htm)
- (F) DMCA §1201(f) provides a reverse-engineering-for-interoperability exemption; EFF has filed amicus briefs on contractual anti-reverse-engineering clauses (Bowers v. Baystate) and on server-emulator interoperability (Blizzard v. bnetd) — [EFF Baystate amicus](https://eff.org/files/filenode/Bowers_v_Baystate/20020918_baystate-amicus.pdf); [EFF-hosted bnetd amicus](https://kittens.eff.org/files/filenode/Blizzard_v_bnetd/050124_finalprofessorsamicusbrief.pdf)
- (F) On 2024-10-25 the Copyright Office denied the VGHF/SPN request for a §1201 exemption allowing remote access to out-of-print games (ESA opposed; "online arcade" concern); current exemptions run to 2027-10-28; VGHF said the ruling pushes researchers toward extra-legal methods — [VGHF statement](https://gamehistory.org/dmca-2024-statement/); [Game World Observer](https://gameworldobserver.com/2024/10/28/dmca-exemption-denied-out-of-print-video-games); [Finnegan summary](https://www.finnegan.com/en/insights/ip-updates/final-rule-issued-in-the-us-copyright-offices-ninth-triennial-section-1201-proceeding.html)

### Inferences
- (I) The two variables that best predict a takedown are (1) whether the project *redistributes* the rights holder's code or assets in playable form, and (2) whether it competes with a *live* commercial service. Eaglercraft, sm64 compiled builds, PSO Reborn, CPR, Nostalrius, Turtle WoW, THJ all tripped one or both; OpenMW, OpenRCT2, DevilutionX, SoH, pokeemerald, RSDK decomps, Return of Reckoning, P99 tripped neither.
- (I) "Decompiled" vs. "clean-room" matters less in practice than what is shipped. SoH and sm64 are decompilations yet untouched because they ship no Nintendo bytes; Eaglercraft was attacked because it shipped a playable decompiled Minecraft. Mojang's "exact source code … need not be in the repo" theory shows a rights holder will claim that a faithful re-creation infringes even without literal copying; GitHub accepted the copyright claims but not the §1201 claim.
- (I) The PSO Reborn takedown (Sept 2026) is the single most on-point precedent: Sega, an MMO with a dormant official service, a browser port, and a takedown within ~10 days of multiplayer going live, executed through an enforcement vendor (MarqVision). It cuts against the assumption that Sega's "no profit, no problem" posture extends to full playable browser ports of its MMOs.
- (I) Blizzard's 2025–2026 campaign (Turtle WoW injunction, Stormforge C&D) and Daybreak v. THJ show that in 2026 publishers of *live* MMOs are escalating from C&Ds to litigation, and that "modified client that connects to a server" is being framed as DMCA circumvention, not just ToS breach.
- (I) GitHub fork-network processing (364, 284, 4,238 repos per notice) means a single notice can erase an entire community's forks; this is why Eaglercraft and Suyu moved to self-hosted Gitea/Forgejo.

## KQ2. The emerging pattern of rights holders licensing or formally tolerating fan servers/ports — what did the fan teams do to get there?

### Takeaway
Formal blessings exist but are rare and share a profile: the official game was *sunset* (City of Heroes, classic EverQuest), the fan project was strictly non-commercial (donations at most, often none), it operated transparently for years without antagonizing the publisher, and it accepted conditions (publisher keeps IP and shutdown rights, consumer-facing legal docs, launcher/distribution changes, non-profit structure). No example was found of a publisher licensing a fan client or server for a game it still operates.

### Cited Findings
- (F) City of Heroes: Homecoming. A secret private server (SCoRE) ran ~2013–April 2019; after the leak, Homecoming launched its first server 2019-04-25 and was founded 2019-05-07 — [Wikipedia: Homecoming Servers](https://en.wikipedia.org/wiki/Homecoming_Servers)
- (F) On 2024-01-04 Homecoming announced NCSOFT had granted it a license to host and further develop City of Heroes, subject to contract conditions; no up-front or recurring license fees; funding remains donation-only; NCSOFT retains the right to demand shutdown; Homecoming must discontinue third-party launchers (Tequila) and provide its own installer/patcher; volunteers sign a contributor agreement; development stays closed-source; Homecoming intends to register as a non-profit (paused during drafting); it will pay one-off legal costs for updated Privacy Policy/ToS; operator is Homecoming Servers, LLC; the license is "limited" and other servers are out of scope; the team cited "over four years" of a positive relationship with NCSOFT — [Homecoming announcement + FAQ](https://forums.homecomingservers.com/topic/47223-ncsoft-homecoming-license-announcement/); [Massively OP, 2024-01-04](https://massivelyop.com/2024/01/04/ncsoft-has-officially-granted-a-city-of-heroes-server-license-to-the-homecoming-crew/); [Game Developer, 2024-01-05](https://www.gamedeveloper.com/business/ncsoft-lets-player-made-city-of-heroes-server-live-with-limited-time-license)

- (I) Common ingredients of the licensed/tolerated cases: (1) the publisher had no live revenue to protect; (2) zero or donation-only money, no perks-for-pay; (3) a legal entity (LLC/non-profit) the publisher could contract with; (4) years of quiet, cooperative operation before any paper was signed; (5) willingness to accept publisher-dictated changes (launcher, ToS, code of conduct) and the publisher's unilateral kill switch.

- (I) For Spiral Knights the key disanalogy is that the game is a live service with monthly releases in 2026 (see KQ3), so Homecoming/P99 are weak templates; the closer templates are "tool-maker tolerated" (KnightLauncher) and "competing client/server shut down" (Turtle WoW, THJ).

## KQ4. Licenses of the open-source Three Rings parts and what they permit

### Takeaway
Clyde and Getdown are BSD-2-Clause (attribution only); Narya, Nenya, Vilya and samskivert are LGPL-2.1 (weak copyleft: modified copies of those libraries must be released under LGPL when distributed, and combined works must let users relink/modify the library). Nothing in these licenses requires releasing the port's own code, but if the port *modifies* Narya/Nenya/Vilya to run in a browser, those modifications must be published under LGPL-2.1 when distributed, and whole-program transpilation raises an unresolved LGPL §6 question.

### Cited Findings
- (F) Clyde README: "The Clyde library is released under the BSD license"; the LICENSE file text is the BSD 2-Clause (Simplified) form — permits redistribution and modification in source or binary form, requiring only retention of the copyright notice; no source-release obligation. Clyde depends on Narya (distributed objects/i18n), Nenya (resources/images/OpenAL), Vilya (networked scenes) and LWJGL — [GitHub threerings/clyde](https://github.com/threerings/clyde); [clyde LICENSE](https://github.com/threerings/clyde/blob/master/LICENSE)
- (F) Getdown LICENSE is BSD 2-Clause, "Copyright (C) 2004-2016 Getdown authors" — [getdown LICENSE](https://github.com/threerings/getdown/blob/master/LICENSE)
- (F) Narya README: "Narya is released under the LGPL"; GitHub sidebar: LGPL-2.1; described as a framework for realtime distributed systems with emphasis on multiplayer online games — [GitHub threerings/narya](https://github.com/threerings/narya)
- (F) Nenya README: released under the LGPL; sidebar LGPL-2.1 — [GitHub threerings/nenya](https://github.com/threerings/nenya)
- (F) Vilya README: released under the LGPL; sidebar LGPL-2.1 — [GitHub threerings/vilya](https://github.com/threerings/vilya)
- (F) samskivert README: released under the LGPL; sidebar LGPL-2.1; COPYING file present; published to Maven Central as com.samskivert:samskivert:1.9 — [GitHub samskivert/samskivert](https://github.com/samskivert/samskivert)

### Inferences
- (I) Porting the BSD parts (Clyde, Getdown) to the browser imposes only notice-retention duties; the port may be closed or open under any license.
- (I) LGPL-2.1 obligations attach to *distribution*. A browser port is distributed to every visitor's browser, so (a) any modified Narya/Nenya/Vilya/samskivert code must be made available under LGPL-2.1 with the modifications; (b) under LGPL-2.1 §6, a work that uses the library must permit users to modify the library and relink, and must provide the library's source or a written offer. Whether a TeaVM/CheerpJ/GWT-style whole-program transpile into one JS/WASM bundle satisfies §6 is an open question with no case law located; the conservative path is to publish the port's entire client source, which moots the question.
- (I) The open-source licenses grant rights independent of the SK ToS; §6.1's ban on reverse engineering "Spiral Knights or any portion thereof" cannot retract rights already granted under BSD/LGPL for those libraries, but it does apply to the proprietary projectx code built on top of them.
- (I) Copyright in these libraries presumably passed from Three Rings to Sega and/or Grey Havens; BSD/LGPL grants are not revocable for already-released versions, so ownership changes do not affect use of the published code.

### Gaps
- The exact LGPL version text in the LICENSE/COPYING files was not read (sidebar labels and READMEs were); confirm "2.1" and whether any "or later" clause exists.
- No project-specific guidance from Three Rings/Grey Havens on how they interpret LGPL for Clyde-based games was found.
- Whether any portions of the public Clyde repo contain Spiral Knights–specific code or assets (which would be outside the BSD grant) was not checked.

## KQ5. The (a)–(e) distinction: porting Clyde vs. decompiling projectx vs. redistributing assets vs. bring-your-own-assets vs. connecting to live servers

### Takeaway
(a) Porting the open-source engine stack is permitted by its licenses; (b) decompiling/transpiling the proprietary projectx jar is a ToS breach for account holders and creates copyright exposure that precedent (Eaglercraft, re3) shows rights holders will act on, with a §1201 theory available if the jar is obfuscated/protected (GitHub rejected Mojang's §1201 claim but honored its copyright claims); (c) redistributing assets is the one thing every rights holder, including Grey Havens explicitly, treats as infringement; (d) having users load their own install directory into the browser is an established pattern (DiabloWeb, pokeemerald-WASM, oot-cleanroom) that no court has ruled on but rights holders have left alone when the *code* was also clean; (e) connecting any third-party client to Grey Havens' live servers is expressly forbidden by §6.13/§6.15 and is the behavior currently being litigated as DMCA circumvention by Daybreak and Blizzard.

### Cited Findings
- (a) Open-source engine licenses — see KQ4 sources: [clyde](https://github.com/threerings/clyde), [narya](https://github.com/threerings/narya), [nenya](https://github.com/threerings/nenya), [vilya](https://github.com/threerings/vilya), [getdown](https://github.com/threerings/getdown/blob/master/LICENSE)
- (b) (F) SK ToS §6.1 and §6.13 prohibit decompiling/disassembling the client and deciphering transmissions, with termination and civil/criminal-liability language — [SK ToS](https://www.spiralknights.com/tos.xhtml). (F) Mojang's theory that presumably-decompiled, recreated code infringes even without literal copying, and GitHub's acceptance of the copyright (not §1201) claims — [github/dmca 2023-03-13](https://github.com/github/dmca/blob/master/2023/03/2023-03-13-mojang-2.md). (F) Take-Two sued over reverse-engineered source even though players still needed the original game — [TorrentFreak](https://torrentfreak.com/take-two-sues-enthusiasts-behind-gta-fan-projects-re3-revc-210903/). (F) Ninth Circuit fair-use precedent protects intermediate copying only where the end product does not contain the plaintiff's expression — [Copyright Office summary of Connectix](https://www.copyright.gov/fair-use/summaries/sony-connectix-9thcir2000.pdf). (F) KnightLauncher builds against `projectx-pcode.jar` as a dependency rather than redistributing it — [KnightLauncher](https://github.com/lucasluqui/KnightLauncher)
- (c) (F) Grey Havens staff explicitly named redistribution of the client or media assets as a violation — [SK forums node/124035](https://forums.spiralknights.com/en/node/124035). (F) Compiled sm64 builds (2020) and PSO Reborn (2026) were taken down; SoH/sm64 decomp/pokeemerald, which ship no assets, were not — [VGC sm64](https://www.videogameschronicle.com/news/nintendo-takes-action-against-mario-64-pc-port/); [Power Up Gaming PSO Reborn](https://powerupgaming.co.uk/2026/09/24/phantasy-star-browser-port-pso-reborn-hit-with-sega-dmca-notice/); [Wikipedia SoH](https://en.wikipedia.org/wiki/Ship_of_Harkinian)
- (d) (F) Browser BYO-asset implementations exist: DiabloWeb requires the user's DIABDAT.MPQ via drag/upload — [DeepWiki diabloweb](https://deepwiki.com/d07RiV/diabloweb); pokeemerald WASM port requires the user's own ROM — [braindetox.kr 2026](https://braindetox.kr/en/posts/pokemon_emerald_webassembly_2026.html); oot-cleanroom runs SoH in-browser — [GitHub oot-cleanroom](https://github.com/andrewnakas/oot-cleanroom). (F) Desktop BYO-asset engines (OpenMW, OpenRCT2, DevilutionX, Xash3D, RSDK) have no recorded takedowns — [OpenMW FAQ](https://openmw.org/faq/); [OpenRCT2](https://en.wikipedia.org/wiki/OpenRCT2); [DevilutionX](https://github.com/diasurgical/devilutionx)
- (e) (F) SK ToS §6.13 (decipher data transmissions), §6.15 (unauthorized servers), §6.2 (server emulators) — [SK ToS](https://www.spiralknights.com/tos.xhtml). (F) Mojang's notice cited that Eaglercraft did not align with the official authentication schema and allowed unauthenticated server connections — [github/dmca 2023-03-13](https://github.com/github/dmca/blob/master/2023/03/2023-03-13-mojang-2.md). (F) Daybreak alleges THJ's required client modifications circumvent its access controls (DMCA theory) — [Aftermath](https://aftermath.site/everquest-the-heroes-journey-lawsuit-update/). (F) Turtle WoW injunction covers modded and "remastered" clients, not just servers — [PCGamesN](https://www.pcgamesn.com/world-of-warcraft/turtle-wow-cease-and-desist). (F) Homecoming's license required dropping the third-party Tequila launcher in favor of an official patcher — [Homecoming announcement](https://forums.homecomingservers.com/topic/47223-ncsoft-homecoming-license-announcement/)

### Inferences
- (I) The BYO-assets pattern solves the *asset* layer only. For Spiral Knights the hard part is the *code* layer: unlike Diablo/OoT/Emerald, where the community wrote or decompiled the engine and the user supplies data, SK's game logic lives in proprietary projectx classes. Three options follow: (1) decompile/transpile projectx and ship it (highest exposure; Eaglercraft/re3 pattern); (2) load the user's own `projectx-pcode.jar` from their install directory at runtime inside a browser JVM, shipping none of GH's bytes (novel; no precedent either way; still a ToS §6.1/§6.13 issue for the developer who reverse-engineers enough to make it work, and §6.15 if it talks to GH servers); (3) clean-room reimplement the game logic against the open-source Clyde/Narya stack (longest, lowest copyright exposure; the Sega v. Accolade/Connectix line is most helpful here, and it is what SoH/OpenMW-style projects are closest to).
- (I) Option (2)/(3) combined with no server connectivity (offline/own-server only) would mirror KnightLauncher's self-imposed rule and the OpenMW/DevilutionX posture; option (e) connectivity to GH's live servers is the single most likely trigger for bans and legal action given 2025–2026 precedent.
- (I) Browser delivery changes the distribution analysis: every page load is a distribution of whatever JS/WASM the site serves. Anything derived from projectx that is served by the site is "distributed"; anything the user drags in from their own install is not distributed by the project. The File System Access API / drag-drop choice is a legal-architecture decision, not just UX.
- (Q) Whether reverse-engineering the SK wire protocol to build an interoperable client is protected by §1201(f) and Ninth Circuit fair use, versus barred by ToS/§1201 as in the bnetd line, is unresolved and fact-specific (is there an access control? is the client obfuscated? does the output contain GH expression?). Not answered by any source found.
- (Q) CFAA exposure for ToS-violating but otherwise authorized access was narrowed by Van Buren v. United States (2021) per general knowledge; not researched in this pass. Flagged for verification.

### Gaps
- No court has ruled on BYO-asset browser ports; tolerance is behavioral, not legal.
- No source establishes whether projectx-pcode.jar is obfuscated or whether SK uses any login-time access control that a third-party client would have to bypass (§1201 relevance).
- No example was found of a browser project that loads a proprietary Java client jar from the user's disk and executes it client-side; that architecture is untested.

## KQ6. Practical risk-reduction playbook used by projects that survived

### Takeaway
Survivors share a checklist: no trademark in the name or domain; ship zero rights-holder code or assets and make users supply their own files; keep the code open and documented so the "no copied expression" claim is checkable; no revenue (not even ad revenue; donations at most, no perks); never touch official servers; expect fork-network takedowns on GitHub and keep a self-hosted mirror; treat a DMCA counter-notice as an invitation to be sued; contact the rights holder before launch, ideally through a legal entity, and be prepared to accept conditions or shut down.

### Cited Findings

### Inferences
- (I) For a Spiral Knights port the highest-leverage moves, in order: (1) no GH code or assets served by the site; (2) no connection to GH servers, with the limitation stated in the README exactly as KnightLauncher does; (3) a non-trademark name and domain (avoid "Spiral", "Knights", "Clockworks", "Haven" in the mark sense); (4) fully open source so a "no copied expression" claim is auditable, with any LGPL-derived code published; (5) zero monetization including ads; (6) a short, polite email to tos@/support@spiralknights.com describing the architecture before any public release, ideally after the above are true, since the 2021 episode shows GH reacts badly to surprise public announcements; (7) self-hosted Git mirror from day one.
- (I) Because SK is live and GH is a small company dependent on it, the most plausible GH response to a public, playable, browser SK that connects to their servers is an immediate ban wave plus takedown, not a license. The most plausible path to a blessing is a tool that adds value to the official game (e.g., a browser-based model viewer / asset browser / offline level viewer) rather than a replacement client.
